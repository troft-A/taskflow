Journal des prompts
Voici des exemples de demandes faites à une IA et les décisions prises par le binôme. Les réponses sont résumées. L’IA propose, c’est nous qui décidons.

Prompt	Réponse IA	Décision gardé/reformulé/rejeté	Pourquoi
1 — User stories : « Propose six user stories pour une application étudiante de gestion de tâches, puis deux idées bonus pour le tri et les filtres. »	Une proposition de huit stories : créer, afficher, modifier, terminer, supprimer et sauvegarder des tâches, puis les trier et les filtrer.	Reformulé	On a gardé les idées utiles, puis on a adapté les phrases à notre projet.
2 — Critères d’acceptation : « Donne des critères simples pour créer une tâche avec un titre, une priorité et une échéance facultative. Pense aussi au titre vide. »	Des critères pour accepter les champs, afficher la tâche et refuser un titre vide.	Gardé	Ces critères sont faciles à vérifier. On les a ajoutés à la story en les ajustant au reste du document.
3 — Données d’une tâche : « Quelles informations minimales faut-il garder pour une tâche ? Pas de code. »	L’IA propose un identifiant, un titre, une priorité, une échéance facultative et un statut ; elle suggère aussi une date de création.	Reformulé	C’est une piste pour plus tard. On vérifiera les champs nécessaires avant de choisir le modèle final.
4 — Priorités MoSCoW : « Classe les fonctions avec MoSCoW pour qu’on commence par un petit socle utile. »	Les fonctions de base sont classées comme indispensables ; le tri et les filtres sont proposés en bonus.	Gardé	Cela correspond à notre découpage entre socle et bonus. On pourra changer l’ordre si on manque de temps.
5 — Relecture : « Relis nos user stories et signale les phrases floues ou difficiles à vérifier, sans ajouter de fonctions. »	L’IA relève des questions sur les dates, le stockage local et la différence entre trier et modifier une tâche.	Reformulé	On a repris les remarques utiles pour clarifier les critères, sans élargir le projet.
6 — Idées hors périmètre : « Ajoute des comptes utilisateurs, une synchronisation cloud, des notifications et des statistiques. »	Ces idées demanderaient des comptes, des services en ligne et plus de temps de développement.	Rejeté	C’est trop ambitieux pour notre version étudiante. On garde une application locale plus simple.
7 — Architecture des fichiers : « Quelle architecture de fichiers pour le dépôt ? (README.md, PROMPTS.md, éventuellement dossier si utile) »	L’IA suggère de commencer avec un README pour le projet et ses stories, et un PROMPTS pour les échanges avec l’IA. Un dossier séparé n’est pas nécessaire pour ces deux documents.	Gardé	C’est simple et suffisant pour le dépôt documentaire actuel. Si on ajoute l’application, on reverra l’arborescence.
8 — Dépôt sur Git : « Comment déposer le projet sur Git (git init, add, commit, remote, push) ? »	L’IA propose les étapes : initialiser le dépôt, ajouter les fichiers, faire un commit, définir le dépôt distant puis envoyer les changements.	Reformulé	Les étapes nous donnent une idée, mais on doit utiliser l’adresse du dépôt et les consignes données par notre cours.
9 — Rendu et étapes : « Qu’est-ce qu’on doit faire exactement pour le rendu / les étapes à suivre ? »	L’IA propose une liste de vérification : relire les stories, compléter les noms, vérifier les fichiers, puis suivre les consignes du cours pour le rendu.	Reformulé	La liste aide à s’organiser, mais elle ne remplace pas les consignes officielles de l’enseignant. C’est nous qui vérifierons ce qui est demandé.
